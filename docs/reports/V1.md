What I did:
- Export every `*_n` texture from each TPF alongside the albedo. The normal is paired by
  name: `x_a` -> `x_n` (`flver::guess_normal`), so it always matches the albedo the material
  already picked instead of re-guessing from the MTD.
- Bumped the model format to SHMD v3: each mesh now writes `u16 len, normal-map name` right
  after the albedo. v2 bins still load (the loader reads the extra string only when version >= 3).
- In `model.rs`, `Mesh::generate_tangents()` runs when a mesh has a normal map (Bevy's PBR
  shader ignores `normal_map_texture` without `ATTRIBUTE_TANGENT`), and the material gets
  `normal_map_texture`.
- Re-exported all 8 models (c0000 base + 5 equipment parts + c1010 + c1020) and confirmed the
  node/mesh counts are unchanged (e.g. c1020 346 nodes / 36 meshes, c0000 base 467 / 0).

Evidence:
- Texture formats (DDS DXGI header of `extracted/chr/c1020.texbnd.d/c1020.tpf`):
  `c1020_*_a` = 99 (`BC7_UNORM_SRGB`), `c1020_*_n` = 98 (`BC7_UNORM`, non-sRGB). So Sekiro
  normals here are 4-channel BC7, not the BC5 the packet expected; Bevy's DDS loader maps 98 ->
  `TextureFormat::Bc7RgbaUnorm` (linear) and 99 -> `Bc7RgbaUnormSrgb`
  (`bevy_image-0.19.1/src/dds.rs:311`).
- Pairing example from the new `extracted/model_c1020.bin`: `#00# albedo=c1020_weapons_a
  normal=c1020_weapons_n`.
- Re-export commands (same FLVER/TPF pairs as the previous bins):
  `sekiro-extract model extracted/chr/c0000.chrbnd.d/c0000.flver - extracted/model_c0000.bin extracted/tex`
  and `... model extracted/chr/c1020.chrbnd.d/c1020.flver extracted/chr/c1020.texbnd.d/c1020.tpf extracted/model_c1020.bin extracted/tex`
  (plus am_m_9000, bd_m_9040, fc_m_0200, lg_m_9000, wp_a_0300, c1010).
- 15 `_n.dds` files now exist in `extracted/tex/`.
